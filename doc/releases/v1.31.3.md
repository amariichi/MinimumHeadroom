# v1.31.3

The Atom HTTP bridge now shares recovery attempts and increases the delay between
failed subnet discoveries, preventing repeated lip-sync failures from triggering
continuous full-network sweeps. Known-address health checks continue, successful
recovery resets the delay, and explicit volume recovery can bypass the wait.

See [Atom bridge recovery](../guides/atoms3r-bridge-recovery.md) for the recovery
timing and activation procedure. This change does not alter network routes or
authentication settings.
